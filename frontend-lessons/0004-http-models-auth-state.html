Environment Config: Centralized API URL

environments/environment.ts defines apiBaseUrl: 'http://localhost:8080/api'. This ensures all API calls use the correct base URL.

ENVIRONMENT CONFIG
// environments/environment.ts
export const environment = {
  production: false,
  apiBaseUrl: 'http://localhost:8080/api'
};

DTO vs. UI Model: Data Transformation

Backend returns DTOs (Data Transfer Objects), which are mapped to UI-friendly models:

Backend DTOUI Model
{ jobId: 'j1', title: 'Developer', employer: { userId: 'u1', companyName: 'Tech Corp' } } { id: 'j1', title: 'Developer', company: 'Tech Corp', companyInitial: 'TC', companyColor: '#FF5733' }

Mapping Logic: Services transform DTOs using helper functions (e.g., mapJob()) to add computed fields like initials and colors.

DTO → UI MODEL MAPPING
Backend DTO                              → UI Model
{
  jobId: "123",
  title: "Software Engineer",
  employer: { companyName: "TechCorp" },
  requirements: ["Java", "Angular"]
}
                │
                ▼ (Frontend mapJob() transform)
Frontend UI Model:
{
  id: "123",
  title: "Software Engineer",
  company: "TechCorp",
  companyInitial: "T",
  companyColor: "#2563eb",
  tags: ["Java", "Angular"]
}

HttpClient: Making API Calls

Angular's HttpClient is configured in app.config.ts via provideHttpClient(). Services inject it to make HTTP requests:

// Example: Fetching jobs
this.http.get<BackendJob[]>(`${this.apiBaseUrl}/jobs/findOpenPositions`).pipe(
  map(backendJobs => backendJobs.map(bj => this.mapJob(bj)))
);

Supports get, post, put, delete methods. Errors are handled via RxJS operators like catchError.

HTTP REQUEST SEQUENCE
1. Service injects HttpClient from app.config.ts
2. Service adds auth token to headers (if user logged in)
3. HttpClient sends request to ${this.apiBaseUrl}/api/endpoint
4. Backend processes request, validates, queries DB
5. Backend returns JSON response (200 OK)
6. HttpClient emits response to service's .pipe()
7. Service maps DTO → UI model
8. Service updates signal
9. Component template renders mapped data

Auth State: Managing Login/Session

AuthService uses Angular signals and localStorage to track the current user:

  • userSignal: Holds the current user (reactive state).
  • localStorage: Persists the user under careerwise_auth_user for session survival.
  • isAuthenticated(): Helper method to check login status.
  • role(): Returns the user's role (candidate/employer).

Login Flow: After /users/login, fetch the role-specific profile (e.g., /jobseekers/read/{userId}) to enrich the user object.

AUTH STATE MACHINE
States:
├─ LOGGED_OUT  ← No user in localStorage
├─ LOGGED_IN    ← User data in localStorage, signals updated
└─ LOADING      ← Fetching profile after login

Transitions:
├─ LOGIN_SUCCESS → Fetch profile → LOGGED_IN
├─ LOGIN_ERROR   → Show toast → LOGGED_OUT
├─ LOGOUT       → Clear localStorage → LOGGED_OUT
└─ AUTH_CHECK    → Verify token → LOGGED_IN/LOGGED_OUT

Simple Explanation

Imagine three roles in a library:

  • Translator (DTO Mapping): Converts complex books (backend DTOs) into easy-to-read summaries (UI models).
  • Messenger (HttpClient): Runs between the reading room (frontend) and archives (backend) to fetch books.
  • Bouncer (Auth State): Checks IDs (login status) and VIP badges (roles) to allow access to restricted sections.

Together, they ensure you get the right information securely! 📚
