Routes: Defining Paths

app.routes.ts is the roadmap of the app. It defines:

  • Paths: URLs like 'dashboard', 'jobs', 'login'.
  • Components: Which page component to load.
  • Layouts: Optional wrapper components (e.g., dashboardLayout for authenticated pages).
  • Guards: canActivate functions to control access.

Layouts: Page Templates

Layouts provide consistent structures for groups of pages:

  • base-layout: Public pages (homepage, about) with a simple header.
  • auth-layout: Login/signup pages with a centered form and background image.
  • dashboard-layout: Authenticated app pages with sidebar navigation and header.

Guards: Access Control

Guards protect routes based on authentication and roles:

  • auth.guard.ts: Checks if the user is logged in. Redirects to /login if not.
  • role.guard.ts: Ensures the user's role (candidate/employer) matches the route's requirements.
// auth.guard.ts Example
export const authGuard: CanActivateFn = (route, state) => {
  const authService = inject(AuthService);
  const router = inject(Router);
  return authService.isAuthenticated() 
    ? true 
    : router.createUrlTree(['/login']);
};
GUARD CHECK SEQUENCE
User attempts to access '/admin'
    │
    ▼
Router matches route → calls canActivate guards
    │
    ▼
auth.guard.ts: checks localStorage.user
    │
    └─ true → continue to next guard
    │
    └─ false → redirect to '/login'
    │
    ▼
role.guard.ts: checks user.role === 'admin'
    │
    └─ true → allow access
    │
    └─ false → redirect to '/dashboard'

End of guard chain: Route loads if all guards pass

Key Points:
├─ Guards run in order defined in canActivate
├─ First guard that returns false prevents access
├─ Guards can return URLs for redirects
└─ Guards run on every route navigation

Simple Explanation

Imagine a hotel:

  • Routes: Room numbers (URLs) like /dashboard (Suite 101).
  • Layouts: Room types—standard (base), luxury (dashboard), or lobby (auth).
  • Guards: Security checks. Keycard required for guest floors (auth guard), VIP lounge needs a special key (role guard).

Routing ensures guests find their rooms, layouts standardize decor, and guards keep areas secure! 🏨

2. Active Recall: What is the difference between auth.guard.ts and role.guard.ts?

Click to reveal answer
  • Auth Guard: Verifies the user is logged in at all.
  • Role Guard: Verifies the logged-in user has the specific role (e.g. Employer or Candidate) required for that page.

3. Active Recall: How does a Layout component like DashboardLayoutComponent know where to render the child route's content?

Click to reveal answer
  • Using the <router-outlet></router-outlet> directive in its template.

4. Active Recall: What happens if a guard returns a UrlTree instead of true?

Click to reveal answer
  • The current navigation is cancelled, and the user is redirected to the URL specified by the UrlTree (e.g. redirecting to /login).
