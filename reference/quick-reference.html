Backend Answers
  • Controller (API), Service (Business Logic), Repository (Database), Entity (Data Structure)
  • JPA ddl-auto=update in application.properties
  • @JsonIgnoreProperties("jobs") on the related entity or careful equals/hashCode implementation.
  • Main.java in backend/src/main/java/za/ac/cput/Main.java
  • Checks for duplicate applications; triggers employer notification.
  • POST /api/applications/apply
  • @CrossOrigin annotation on the controller.
  • Catches exceptions globally and returns standardized JSON error responses.
Frontend Answers
  • client/src/environments/environment.ts
  • DTO: Raw data from API; UI Model: Processed for display, includes computed fields.
  • inject() imports dependencies directly, reducing constructor boilerplate.
  • Tracks applied job IDs for O(1) lookup; Set is used for performance.
  • Declarative (RouterLink) and Programmatic (Router.navigate()).
  • sm:, md:, lg:, xl:
  • Auth Guard: checks login; Role Guard: checks role permission.
  • Auth signals + localStorage entry careerwise_auth_user.
Integration & Testing Answers
  • Frontend calls GET /api/jobseekers/read/{userId} or /employers/read/{userId}.
  • npm test in the client directory.
  • Backend tests: mvn test or similar (check backend README); Type checks: npm run typecheck (if applicable).
  • jobSeekerId, jobId, notes.
  • Used to create JobApplication objects, ensuring consistency and encapsulation.
  • Architecture: Controller ? Service ? Repo layers (Lesson 0001)
  • Consumption: HttpClient + apiBaseUrl + mapping (Lesson 0004)
  • End-to-end: Apply flow with Network tab (Lesson 0003)
  • Auth: users/login + enrich with jobseeker/employer (Lesson 0005)
  • Side effects: Notifications on create/apply/status change (Lesson 0005)
  • Resume: multipart upload/download (Lesson 0005)
  • Guards/Errors: Route protection + global handling (Lesson 0005)
