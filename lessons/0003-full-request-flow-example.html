0003 - Full Request Flow Example (Apply for a Job)

Back to Mission | Previous

Lesson Goal

Trace the full journey of a job application, from the UI click to database storage and back.

Scenario: A logged-in job seeker clicks "Apply Now" → Frontend sends request → Backend creates application → Employer gets notified → UI updates. 
UI Click "Apply" ──▶ Frontend Service ──▶ Backend Controller ──▶ DB Save 
                               │                                │
                               └────────── Notification (Email/UI) ──▶ Employer

Step-by-Step Breakdown

  1. UI Trigger

    On the job details page, the user clicks "Apply Now". The Angular component calls ApplicationService.apply(jobId, notes).

    ┌─────────────────────────────────────────────────────────────┐
│                    JOB PAGE COMPONENT                        │
├─────────────────────────────────────────────────────────────┤
│ [ Search ] [ Company Filter ] [ Salary Range ]               │
│ [ Job Card 1 ]      [ Job Card 2 ]      [ Job Card 3 ]       │
│ [ Apply Button ]    [ Apply Button ]    [ Apply Button ]    │
└─────────────────────────────────────────────────────────────┘
  2. Frontend HTTP Call

    POST /api/applications/apply with JSON body:
    { "jobSeekerId": "user123", "jobId": "j456", "notes": "Excited to apply!" }

    Sent via Angular's HttpClient.

  3. Backend Controller

    JobApplicationController receives the payload, validates fields, and calls applicationService.apply().

    // Snippet from JobApplicationController.java
public JobApplication apply(@RequestBody Map<String, String> payload) {
    String jobSeekerId = payload.get("jobSeekerId");
    // ... validation
    return applicationService.apply(jobSeekerId, jobId, notes);
}
  4. Service Layer Magic

    ApplicationsServiceImpl orchestrates the logic:

    • Checks for duplicates: findByJobSeekerAndJob()
    • Loads JobSeeker and Job entities from repositories
    • Builds JobApplication using JobApplicationFactory
    • Saves to DB: applicationRepository.save(app)
    • Side Effect: Triggers employer notification via notificationService
    Application Flow:
├─ Service starts ──▶ Create JobApplication → Save to DB
├─ Database updates  │
└─ Service notifies  ──▶ Create Notification → Send to Employer

Side Effect Chain:
1. User clicks "Apply"
2. Service: validate, duplicate check, save, notify
3. UI updates: new application appears, button disabled
4. Employer receives notification
  5. Database Persistence

    IJobApplicationRepository (Spring Data JPA) saves the entity to MySQL. Relationships between JobApplication, Job, and JobSeeker are mapped via JPA annotations.

  6. JSON Response

    The saved entity (with related data) is serialized by Jackson and sent back as JSON:

    {
  "id": "app789", "jobSeeker": { ... }, "job": { ... }, "notes": "Excited to apply!"
}
  7. Frontend Mapping & State Update

    ApplicationService maps the JSON to a UI model, updates Angular signals, and returns an observable. The Dashboard component reacts by:

    • Adding the application to the list
    • Disabling the "Apply" button
    • Showing a success toast

Code Spotlight

  • Backend Apply Logic: ApplicationsServiceImpl.java:120-220 (duplicate check, save, notify)
  • Factory Pattern: JobApplicationFactory.buildJobApplication()
  • Frontend Service: application.service.ts:150-170 (HTTP call, mapping, signal update)

Key Takeaways

  • Vertical Slice: A single request touches all layers (UI → DB → UI).
  • Side Effects: One action (apply) triggers multiple outcomes (save, notify).
  • State Management: Frontend uses signals to reactively update the UI.

Simple Explanation

Imagine applying for a job is like sending a letter:

  1. You drop the letter (click "Apply").
  2. The postman (HTTP) delivers it to the company (backend).
  3. The HR manager (Service) checks if you already applied, files your letter (saves to DB), and tells the boss (employer notification).
  4. The company (DB) keeps your letter safe.
  5. You get a confirmation note (JSON response) and your mailbox (UI) updates.

That's how your application travels through the system! 📬

  • It checks for duplicate applications to prevent re-applying.
  • It triggers a notification to the employer via notificationService.

3. Active Recall: How does the frontend ApplicationService update the UI state after a successful application?

Click to reveal answer
  • It updates Angular signals (e.g., applicationsSignal), which causes components to re-render automatically.

4. Active Recall: What JSON body fields are typically sent in the POST /api/applications/apply request?

Click to reveal answer
  • jobSeekerId, jobId, and notes.
