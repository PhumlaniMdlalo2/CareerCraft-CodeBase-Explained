0001 - Backend Basics & Architecture

Back to Mission | Notes | Resources

Lesson Goal

Grasp how the Spring Boot backend is structured, its layers, and how they work together to handle requests.

Tech Stack: The Tools We Use

  • Spring Boot 3.2.5: The framework that simplifies Java backend development (defined in pom.xml).
  • Spring Data JPA: Makes database interactions easy with Java Persistence API.
  • Lombok: Reduces boilerplate code (e.g., getters/setters) with annotations like @Data.
  • MySQL/H2: Databases used for development (configured in application.properties).
  • Jackson: Converts Java objects to JSON and vice versa.

Layering: The Backend's Org Chart

Think of the backend as a company with specialized departments:

LayerPurposeAnalogyCode Example
Controller (REST) Handles HTTP requests/responses Receptionist Controller/JobController.java
Service Executes business logic Manager Service/IJobService.java → JobServiceImpl.java
Repository Talks to the database Librarian repository/IJobRepository.java
Domain/Entity Represents data tables Books in the library domain/Job.java, User.java
Factory Helps create objects (e.g., Builder pattern) Assembly Line factory/JobApplicationFactory.java
Typical Request Flow:
  1. Controller (Receptionist) gets an HTTP request.
  2. Calls Service (Manager) to handle the work.
  3. Service asks Repository (Librarian) for data.
  4. Repository fetches data from the database.
  5. Data is sent back as JSON (like a report).
HTTP Request → [Controller] → [Service] → [Repository] → [Database]
      ↑             |           |             |              |
      └─────────────┴───────────┴─────────────┴──────────────┘
                    (JSON Response)

Entry Point: Where It All Starts

@SpringBootApplication
public class Main {
    public static void main(String[] args) {
        SpringApplication.run(Main.class, args);
    }
}

This Main.java is the ignition switch that starts the Spring Boot app.

Configuration: The Rulebook

application.properties sets up rules for:

  • Database connections (MySQL/H2)
  • JPA: ddl-auto=update (auto-updates database schema)
  • SQL logging (to see queries in the console)
  • Multipart file uploads (for resumes)
  • Jackson date formatting

Key Takeaways

  • Controllers use @RestController and @RequestMapping to handle HTTP methods.
  • Services are injected into controllers via constructor (dependency injection).
  • Repositories extend JpaRepository to get CRUD methods for free.
  • Entities map to database tables with JPA annotations.
  • Relationships (e.g., Job → Employer) use annotations like @ManyToOne.

Simple Explanation

Imagine the backend as a restaurant kitchen:

  • Controller: Waiter taking your order (HTTP request).
  • Service: Chef preparing the meal (business logic).
  • Repository: Pantry manager fetching ingredients (database data).
  • Domain/Entity: The ingredients themselves (data models).
  • JSON: The plate that delivers the meal to your table (response format).

Every request follows this flow to get you the data you need! 🍽️
