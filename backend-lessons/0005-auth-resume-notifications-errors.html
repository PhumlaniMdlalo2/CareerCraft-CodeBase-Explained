0005 - Auth, Resume, Notifications, Errors & Guards

Back to Mission | Previous | Quick Reference

Lesson Goal

Master authentication, resume handling, notifications, error management, and route protection—critical for a secure and user-friendly app.

Authentication Flow: How Users Log In

Key Point: Simple email/password auth. No JWT; frontend uses localStorage and route guards. 
UI Action (Login) ──▶ Controller ──▶ Service ──▶ DB
      ▲                                         │
      └────── localStorage (AuthState) ◀────────┘
                   │
                   ▼
      Guards check state → Route Access

Backend Auth Endpoints

  • POST /api/users/signup: Creates base user (email, password).
  • POST /api/users/login: Validates credentials, returns user ID.
  • POST /api/jobseekers/create or /employers/create: Role-specific profile creation.

Frontend AuthService

  1. Signup: Splits name, posts to role-specific endpoint, stores enriched user in localStorage.
  2. Login: Calls /api/users/login, then fetches full profile from /api/jobseekers/read/{userId} or /api/employers/read/{userId}.
1. Signup: POST /api/users/signup (Base User)
2. Profile: POST /api/jobseekers/create (Enriched Data)
3. Login: POST /api/users/login (Credentials)
4. Session: GET /api/jobseekers/read/{id} (Current Profile)

Resume Upload/Download: Handling Files

Backend (Multipart Handling)

  • POST /api/jobseekers/{userId}/resume: Accepts multipart/form-data, saves file to server.
  • GET /api/jobseekers/{userId}/resume: Returns file as Resource with correct MIME type.

Config: spring.servlet.multipart.max-file-size=5MB in application.properties.

Frontend (Angular HTTP)

  • uploadResume(): Uses HttpClient with FormData to POST file.
  • downloadResume(): GETs file as Blob, triggers browser download.
Upload:   FormData(file) ──▶ POST /api/jobseekers/{id}/resume ──▶ File System
Download: GET /api/jobseekers/{id}/resume ──▶ Blob (PDF) ──▶ Browser View

Notifications: Side Effects in Action

Notifications are created in service layers after key actions:

  • New Job Posted: JobServiceImpl notifies all job seekers.
  • Application Received: ApplicationsServiceImpl alerts the employer.
  • Status Change: Applicant gets update when status changes.
JobServiceImpl.create()            ──▶ notify all job seekers
ApplicationsServiceImpl.apply()    ──▶ notify job employer
ApplicationsServiceImpl.update()   ──▶ notify applicant

Global Error Handling: Centralized Control

GlobalExceptionHandler catches exceptions and returns structured JSON errors:

@RestControllerAdvice
public class GlobalExceptionHandler {
    @ExceptionHandler(JobNotFoundException.class)
    public ResponseEntity<ErrorResponse> handleJobNotFound(JobNotFoundException ex) {
        return ResponseEntity.status(HttpStatus.NOT_FOUND).body(new ErrorResponse("JOB_NOT_FOUND", ex.getMessage()));
    }
}

Custom exceptions (e.g., JobNotFoundException) and validations (e.g., deadline checks) ensure clear error messages.

Route Guards: Protecting Access

  • auth.guard.ts: Checks localStorage for user; redirects to login if missing.
  • role.guard.ts: Verifies user role matches route requirements (e.g., employer-only pages).
Route Request ──▶ auth.guard (Is Authenticated?) ──▶ role.guard (Has Role?) ──▶ Page Render
                         │                                  │
                         └────── Redirect /login ───────────┴────── Redirect /dashboard

Simple Explanation

Imagine a hotel:

  • Auth: Checking in (login) and getting a room key (localStorage).
  • Resume: Storing luggage (upload) and retrieving it (download).
  • Notifications: Messages slipped under your door (new job alerts, applicant notifications).
  • Errors: Complaint desk handling issues (centralized error responses).
  • Guards: Security checking keys (auth) and room access (role-based routes).

Everything works together to keep the hotel (app) running smoothly! 🏨

Key Takeaways

  • Auth uses simple email/password with role-specific profiles.
  • Resume handling uses multipart requests, limited to 5MB.
  • Notifications are decoupled side effects in services.
  • Global error handler ensures consistent error responses.
  • Route guards enforce authentication and authorization.
