Demo Script (3-5 Minutes)

  1. Intro (30s)

    Explain architecture: Angular UI → Services → Spring Boot API (/api) → Controller → Service → Repository → DB.

    Angular UI  ──▶  Spring Boot REST (/api)  ──▶  Service Layer  ──▶  JPA / DB
  2. API Surface (30s)

    Show JobController.java and JobApplicationController.java. Highlight endpoints: /api/jobs/findOpenPositions, /api/applications/apply.

  3. Frontend Consumption (45s)

    Open job.service.ts. Show apiBaseUrl from environment.ts, HttpClient call, and mapJob() converting backend DTO to UI model.

  4. Live: Browse Jobs (1m)

    Navigate to Jobs page. Use Network tab to show GET request → JSON response → UI rendering mapped jobs.

  5. Live: Auth & Apply (1.5m)

    Login as candidate. Show auth.service.ts fetching profile. Click "Apply Now" → Network shows POST /api/applications/apply. Backend ApplicationsServiceImpl creates app and triggers employer notification. UI updates applied state.

    1. Click "Apply" ──▶ POST /api/applications/apply
2. Service logic ──▶ Check duplicate, Save DB
3. Side Effects  ──▶ Notification (Employer gets alert)
4. UI Update     ──▶ Reactively shows applied state
  6. Wrap-up (1m)

    Summarize: Resume upload/download, notifications, guards, error handling. Reference Quick Reference guide.

Talking Points

  • Consumption: "Frontend services act as translators, calling backend APIs and converting responses to UI-friendly models."
  • Connections: "Controllers define the contract, services enforce logic, repositories persist data, and the frontend reacts to state changes."
  • Side Effects: "Applying for a job doesn't just save data—it triggers notifications to employers, showing business logic in action."
  • Integrity: "Validations (e.g., deadlines, duplicates) ensure data consistency across layers."
  • Security: "Route guards protect pages based on user roles, while CORS allows frontend-backend communication in dev."

Simple Explanation

Think of the demo as a theater play:

  • Actors: Frontend (UI), Backend (API/Logic), Database (Storage).
  • Script: The demo steps are the scene directions.
  • Props: Code files, Network tab, and UI interactions.
  • Audience: Your presentation viewers need to see how all parts work together seamlessly.

Practice makes perfect—rehearse each "scene" until smooth! 🎭

Key Takeaways

  • Use the Network tab to visually prove API consumption.
  • Show end-to-end flows (UI → DB → UI) to demonstrate connectivity.
  • Highlight transformations (DTO → UI model) and side effects (notifications).
  • Have backup talking points and code snippets ready.
