Lesson Goal

Understand how the frontend communicates with the backend via REST API endpoints. Map the end-to-end flow of a typical request (e.g., fetching jobs, submitting applications).

Base URL & Setup

  • Backend API base: http://localhost:8080/api (Defined in client/src/environments/environment.ts)
  • Angular HttpClient uses environment.apiBaseUrl
[Frontend: Port 4200] ───────── /api/* ─────────▶ [Backend: Port 8080]
  (environment.ts)                                 (REST Controllers)

Jobs Example: End-to-End Flow

1. Frontend Trigger

User visits the Dashboard/Jobs page. Angular’s JobService is called to fetch open positions.

2. API Call

HTTP Method: GET
Endpoint: /api/jobs/findOpenPositions
Request: No parameters needed.

3. Backend Processing

Controller: JobController.java handles the request.
Service: IJobService → JobServiceImpl fetches data from the database.
Repository: IJobRepository queries the jobs table.

UI Component
    │
    ▼ (invokes method)
JobService (Angular)
    │
    ▼ (HTTP GET /api/jobs/findOpenPositions)
JobController (Spring Boot @RestController)
    │
    ▼ (delegates logic)
JobServiceImpl (Service Layer)
    │
    ▼ (queries)
JobRepository (Spring Data JPA)
    │
    ▼ (SQL SELECT)
MySQL Database

4. Response & Mapping

Backend Returns: BackendJob objects (includes nested employer data, requirements[], dates as strings).
Frontend Maps: Converts BackendJob to UI-friendly Job model via mapJob() (adds companyInitial, companyColor, postedTime, extracts tags).

Backend DTO (Raw API shape):
{
  jobId: "123",
  title: "Software Engineer",
  employer: { companyName: "TechCorp" },
  requirements: ["Java", "Angular"]
}
                │
                ▼ (Frontend mapJob() transform)
Frontend UI Model:
{
  id: "123",
  title: "Software Engineer",
  company: "TechCorp",
  companyInitial: "T",
  companyColor: "#2563eb",
  tags: ["Java", "Angular"]
}

Key Endpoints

Jobs

MethodEndpointDescription
GET/api/jobs/findOpenPositionsFetch all open jobs
GET/api/jobs/searchSearch jobs by criteria
POST/api/jobs/createCreate a new job (employer)

Job Applications

MethodEndpointDescription
POST/api/applications/applySubmit a job application
GET/api/applications/jobseeker/{id}Get applications for a job seeker

Auth Flow

  1. Login: POST /api/users/login → Returns userId.
  2. Enrich Profile: GET /api/jobseekers/read/{userId} (for job seekers) or GET /api/employers/read/{userId} (for employers).
1. Login: POST /api/users/login (Credentials) ──▶ UserID
2. Enrich: GET /api/jobseekers/read/{UserID}  ──▶ Full Profile

Simple Explanation

Imagine the backend is a restaurant kitchen and the frontend is the waiter.

  • Menu (API Endpoints): The waiter uses the menu (e.g., "/api/jobs") to tell the kitchen what you want.
  • Order Flow: You say "Get open jobs" → Waiter tells kitchen → Kitchen fetches from pantry (DB) → Waiter brings food (data) → You eat (see jobs)!
  • Special Requests: Like applying for a job? The waiter sends your application to the kitchen, which saves it in the pantry.

Moral: APIs are like waiters and chefs working together to get you what you need! 🍔↔️🍴

Key Takeaways

  • Frontend talks to backend via HttpClient with base URL /api
  • Controllers expose RESTful endpoints; services contain business logic
  • Frontend often maps backend DTOs to UI models for display
  • Cross-origin allowed (@CrossOrigin) - dev setup
